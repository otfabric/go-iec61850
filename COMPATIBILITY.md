# Compatibility Policy

## Semantic versioning

go-iec61850 follows [Semantic Versioning 2.0.0](https://semver.org/).

The module path is `github.com/otfabric/go-iec61850`. The v1 series is
API-stable.

## What patch releases may change

Patch releases (v1.x.y → v1.x.z) may:

- Fix protocol encoding or decoding defects.
- Correct IEC 61850 semantic behaviour (e.g. RCB attribute handling, control
  state machine transitions, dataset resolution).
- Add tests and documentation.
- Improve error messages.

**Important for protocol libraries:** a standards-correct behavioural fix can
change observable on-wire or callback behaviour while remaining Go
API-compatible. Such corrections are made in patch releases without being
classified as breaking changes.

## What minor releases may change

Minor releases (v1.x → v1.y) may:

- Add backward-compatible exported types, functions, methods, and constants.
- Add optional fields to option structs (zero-value safe where possible).
- Add new IEC 61850 services or CDCs.
- Add optional methods to handler interfaces via interface segregation.

## Breaking changes

Breaking public API changes are reserved for a future v2 major release.

## Minimum supported Go version

The minimum supported Go version tracks the two most recent stable releases.
The current minimum is recorded in `go.mod`.

## GOOSE

The `goose` package follows the same policy as the root package. The
on-wire encoding follows IEC 61850-8-1; fixes that change the bytes sent
(e.g. a field encoding) are made in patch releases. The `Transport`
interface may gain implementations but not methods within v1. Raw
transports are available on Linux, macOS and the BSDs; other platforms
return `ErrUnsupportedPlatform`.

## SCL types

The types generated by the `scl` package and the `sclgen` tool are part of the
public API. New fields may be added in minor releases; field removals or
renames require a major release.

## Interoperability

The library is tested against pinned Docker images of
[mms-interop](https://github.com/otfabric/mms-interop) adapters for four
independent stacks. The `TestLibIEC*` suites in `interop/` are
stack-parametrized (`IEC61850_PEER_STACK`); iec61850bean has its own
`TestBean*` suites; the GOOSE suites run against every stack with GOOSE
commands. A step the stack does not implement is answered by the adapter
with `{"event":"error","code":"unsupported"}` (or an `unsupported` step
error) and the test is skipped with that reason.

### Per-stack matrix

Results with the mms-interop v0.3.0 images pinned in
`.github/workflows/interop.yml`.

|---|:---:|:---:|:---:|:---:|
| License | GPL-3.0 | Apache-2.0 | GPL-3.0 | MIT OR Apache-2.0 |
| Go client → stack server: browse, read/write, datasets | ✓ | ✓ | ✓ | ✓ |
| Stack client → Go server: browse, read/write, datasets | ✓ | ✓ | ✓ | ✓ |
| URCB reporting (both directions) | ✓ | ✓¹ | ✓ | ✓ |
| URCB TrgOps/IntgPd write on the stack server | ✓ | ✓ | ✓ | denied² |
| Direct / SBO control (both directions) | ✓ | ✓ | ✓ | ✓ |
| SBOw (enhanced security) | ✓ | skip³ | ✓⁴ | ✓ |
| CDC reads DPS (Dbpos) / BCR from the stack server | skip⁵ | skip⁵ | ✓ | ✓ |
| MMS file services | ✓ | ✓ | ✓ | unsupported⁶ |
| GetNameList from the SCL model | ✓ | ✓ | ✓ | run-time registries⁶ |
| GOOSE: Go publisher → stack subscriber | ✓ | n/a | ✓ | ✓ |
| GOOSE: stack publisher → Go subscriber (SCL-validated) | ✓ | n/a | ✓ | ✓ |
| GOOSE: Go IED server GoCB → stack subscriber | ✓ | n/a | ✓ | ✓ |
| Sampled Values / R-GOOSE | n/a | n/a | n/a | unsupported⁶ |

¹ The iec61850bean server does not support URCB reservation (`Resv`);
that negative test is skipped.
² The fixture ICD declares `ReportSettings trgOps="Fix" intgPd="Fix"`;
iec61850-rust enforces it (object-access-denied), the others accept the
write. The integrity-period test is skipped for iec61850-rust.
³ iec61850bean's server does not expose `SBOw[CO]` as writable.
⁴ Requires the server's CommandTermination (added in v1.1.0); the
dscsystems controller waits for it.
⁵ The libiec61850 and iec61850bean adapter servers do not apply the
`GGIO1.DPS1.stVal` / `MMTR1.TotVAh.actVal` initial values of
`values.json` and serve type defaults, so the read cannot be compared with
the fixture. The Go server side is covered by `TestGoServer_CDC_*`.
⁶ Not implemented by iec61850-rust: no MMS file services, no SVCB or
R-GOOSE; its GetNameList answers from run-time registries rather than the
SCL. Adapter steps for these answer `unsupported` and are skipped.

Stack-specific deviations are listed in mms-interop
`fixtures/capabilities.json` (`knownLimitations`). Interoperability with physical IEDs has not yet been formally
established. Corrections required by real-device behaviour may be made in patch
releases.

## Protocol behaviour

This library aims to be correct per IEC 61850 Edition 2. Where the standard is
ambiguous or real-world deviations are observed, the chosen behaviour is
documented in `INTEROP.md` and `KNOWN_LIMITATIONS.md`. Correcting a deviation
from the standard is not considered a breaking change.
